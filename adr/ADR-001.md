# ADR-001 — Núcleo de domínio Python independente para o MVP

## Status
Aceita.

## Contexto
A Entrega 1 exige validar as regras de negócio do DOA FÁCIL antes de
investir tempo em interface, banco de dados ou integração de pagamento.
A equipe precisa de um artefato pequeno, fácil de revisar e de testar
automaticamente, que sirva de base sólida para as próximas sprints.

## Decisão
Implementar o MVP como um núcleo de domínio Python puro (`app/domain.py`),
sem dependências de frameworks web, ORMs ou SDKs de pagamento. A validação
do comportamento é feita exclusivamente por meio de testes automatizados
com `pytest`.

## Alternativas consideradas
- **API HTTP completa com banco de dados desde a Entrega 1**: descartada
  por aumentar o escopo e o risco de a equipe não conseguir validar as
  regras de negócio a tempo.
- **Protótipo apenas em planilha/mock sem código**: descartada por não
  gerar nenhum artefato testável, contrariando a exigência de harness de
  testes da disciplina.

## Consequências
- **Positivas**: entrega pequena, rápida de rodar (`pytest -q` roda em
  milissegundos), fácil de revisar em Pull Request e totalmente reprodutível
  via Docker.
- **Negativas / limitações aceitas**: o sistema ainda não possui interface
  gráfica, API HTTP, persistência em banco de dados, autenticação,
  notificações ou processamento de pagamento real. Essas frentes ficam
  documentadas como escopo futuro no `Backlog do Produto - DoaFácil`.
