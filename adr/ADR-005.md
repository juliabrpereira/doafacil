# ADR-005 — Critério de cobertura dos testes automatizados

## Status

Aceita

## Contexto

A Entrega 2 exige evidências dos testes automatizados e uma análise da cobertura do código. O projeto utiliza `pytest` para executar os testes e `pytest-cov` para medir quais partes da aplicação são exercitadas.

A cobertura de 100% é um requisito para o módulo de domínio (`app/domain.py`), conforme o RNF04. A interface web (`app/web.py`) também é avaliada pela ferramenta de cobertura, mas não possui a mesma meta obrigatória de 100%.

## Decisão

Utilizar `pytest` e `pytest-cov` para executar os testes automatizados e medir a cobertura dos módulos da aplicação. O módulo `app/domain.py` deve manter 100% de cobertura, enquanto a cobertura de `app/web.py` deve ser apresentada e analisada, sem exigir que alcance 100%.

## Alternativas consideradas

- **Executar apenas os testes automatizados**: verifica o comportamento implementado, mas não mostra quais linhas de código não foram exercitadas.
- **Exigir 100% de cobertura em todos os módulos**: aumentaria a meta de cobertura da interface web, embora esse não seja o requisito definido para o domínio.
- **Medir a cobertura sem estabelecer uma meta para o domínio**: permitiria acompanhar os testes, mas não garantiria o atendimento ao RNF04.

## Consequências

- **Positivas**: a cobertura passa a ser uma evidência mensurável, facilita a identificação de trechos não testados e ajuda a verificar o cumprimento do RNF04.
- **Negativas / limitações aceitas**:
  - Uma cobertura de 100% não garante, por si só, que todos os comportamentos estejam corretos.
  - A interface web pode apresentar linhas não cobertas, que devem ser analisadas e documentadas.
  - Os resultados de cobertura precisam ser atualizados quando o código ou os testes forem modificados.
- **Revisão futura**: reavaliar a estratégia de testes conforme a aplicação evoluir, especialmente se forem adicionados persistência de dados, novas rotas ou outros componentes.
